# AD5M Guard

Программа для Windows, которая смотрит на ваши FlashForge Adventurer 5M через их же камеру
и ставит печать на паузу, если что-то пошло не так: пластик начал сыпаться «спагетти»
или деталь оторвалась от стола.

Печать идёт часами, и сорванная деталь за это время превращается в ком пластика на весь стол.
AD5M Guard замечает это примерно за минуту и останавливает принтер. Подойдёт и для одного
принтера дома, и для фермы.

## Как начать

1. Скачайте архив со страницы [Releases](https://github.com/nazbav/ad5m-guard/releases/latest) и распакуйте.
2. Запустите `AD5M-Guard.exe` — откроется панель в браузере.
3. На принтере: Настройки → Сеть → включите «Только локальная сеть» и запомните код.
4. В панели: «Найти в сети» → «Добавить» → введите код → «Сохранить».

Сначала посмотреть без принтера: `AD5M-Guard.exe --demo` — три виртуальных принтера,
на одном печать срывается, и программа её останавливает.

## Что умеет

- все принтеры на одном экране: камера, прогресс, температуры, сколько осталось;
- пауза, продолжить, отмена, свет — прямо из панели;
- сама ставит на паузу при спагетти и отрыве детали, может прислать снимок в Telegram;
- стоковая прошивка и Klipper (ZMOD);
- всё работает на вашем компьютере: без облака, без подписки, видеокарта не нужна.

## Насколько точно

На 96 часах записанных печатей — ни одной ложной остановки. Большой ком пластика ловит уверенно,
мелкий брак может пропустить: настоящих сбоев для обучения пока мало. Хотите помочь — в программе
«Настройки» → «Скачать данные для дообучения», и напишите нам в [Issues](https://github.com/nazbav/ad5m-guard/issues).

Бесплатно, с открытым кодом (AGPL-3.0). Подробная инструкция — [docs/USER_GUIDE.md](docs/USER_GUIDE.md).

# Для разработчиков

## Устройство программы (`guard/`)

Панель-приложение для Windows (`AD5M-Guard.exe`): добавить принтер (адрес, код доступа,
адрес камеры), видеть камеры и состояние парка, управлять печатью (пауза / продолжить /
отмена / свет), автоматическая остановка при сбое, журнал тревог со снимками, Telegram.
Инструкция пользователя — `docs/USER_GUIDE.md`.

Протоколы (выбираются сами при «Проверить подключение»):

| прошивка | канал | что используется |
|---|---|---|
| стоковая FlashForge | HTTP 8898 (+ TCP 8899 запасной) | `/detail`, `/control` (serialNumber + checkCode из «Только LAN»); `~M601/M115/M119/M27/M105/M25/M24/M26/M146` |
| Klipper (ZMOD, Klipper Mod) | Moonraker 7125 | `/printer/objects/query`, `/printer/print/pause|resume|cancel`, `/server/webcams/list` |
| камера | mjpg-streamer 8080 | `?action=snapshot`, при его отсутствии — первый кадр `?action=stream` |

Слои (зависимости только внутрь):

```
guard/domain      модели, правило тревоги (policy.py) — чистая логика, без сети и файлов
guard/ports.py    интерфейсы: PrinterDriver, Camera, Detector, Notifier, ConfigStore, EventStore
guard/adapters    FlashForge HTTP/TCP, Moonraker, HTTP-камера, ONNX Runtime, YAML/SQLite, Telegram
guard/services    FleetService — опрос парка, пакетное распознавание, решения, команды
guard/web         Flask API + одностраничная панель (static/index.html)
guard/app         запуск: данные, журналы, одна копия, трей, автозапуск, демо
emulator/         виртуальные AD5M: те же порты и протоколы, камера на записях, неисправности
```

Запуск из исходников и проверка без принтеров:

```bat
.venv-build\Scripts\python -m guard.app.main --demo      :: панель + 3 эмулированных принтера (сбой на AD5M-01)
.venv-build\Scripts\python -m emulator                   :: отдельный эмулятор с пультом http://127.0.0.1:8790/
.venv-build\Scripts\python -m pytest tests\product       :: контракт драйверов против эмулятора, сервис, API, e2e
.venv-build\Scripts\python packaging\build.py            :: тесты → exe → проверка exe в демо → zip в dist\
```

Модели в exe — ONNX (`tools/export_onnx.py` → `build/models`), PyTorch не нужен.
Кадры демо — `tools/make_demo.py` → `build/demo`.

**Правило тревоги** (`guard/domain/policy.py`, всё меняется в панели) — главная цель
минимум ложных остановок:

- печать **останавливают только** классы `stop_on` (спагетти, отрыв модели);
  `notify_on` (пластина не видна, стекло вместо PEI) — только уведомление; прочее видно в панели;
- проблема должна быть на текущем кадре и ещё минимум на 2 из 4 предыдущих (`3 из 5`),
  **на том же месте** (IoU рамок ≥ 0.2) — ложные срабатывания «прыгают» по кадру;
- рука в кадре — история сбрасывается и 10 с не судим (человек у принтера);
- перерыв в наблюдении (пластину не видно, камера или принтер молчали) — история сбрасывается;
- судим только в статусе «печатает»; одна остановка на печать; повтор тревоги не чаще раза в 10 мин.

## Модели

Две модели YOLO26:

| модель | что ищет | на чём учится |
|---|---|---|
| **defects** (`config/defects.yaml`) | спагетти, струны, коробление, трещины, сопли/мусор, отрыв модели | кадры AD5M + фото брака из интернета |
| **scene** (`config/scene.yaml`) | пластина PEI, голова, пластина лежит криво, тестовая линия, рука, слетевшая крышка обдува | только кадры AD5M |

Почему две: стол и голова размечены только на кадрах AD5M, а на интернетных
фото те же объекты есть, но не размечены. В одной модели это учит не тому.
Камера и ракурс у всех AD5M одинаковые, поэтому модель сцены работает на
любом AD5M, хотя учится на кадрах одного.

Открытый некоммерческий проект, **GNU AGPL-3.0** (`LICENSE`) — та же лицензия, что у Ultralytics
YOLO, на котором обучены модели. Лицензии библиотек, входящих в exe, — `THIRD_PARTY_LICENSES.txt`

## Инструменты для моделей (запуск из Windows)

Ярлык **«Детектор брака AD5M»** на рабочем столе (или `start.bat` в папке проекта)
открывает окно со всеми действиями: проверка модели на видео/кадрах/живой камере,
прогон по всем записанным печатям, эмуляция принтеров вместе с сервисом, сервис для
настоящих принтеров, отчёты о моделях, обучение, отбор кадров и разметка.
Каждая задача идёт в своём окне консоли (оно не закрывается само — видно итог),
отчёты открываются в браузере. На видео или zip с кадрами можно также просто
перетащить файл на `run_video.bat`.

«Разметка кадров» (`label_tool.py`) — просмотр и правка разметки без Roboflow:
← → кадры, мышью — новая рамка, клик — выделить, Delete — удалить, цифры — класс.

## Быстрый старт (командная строка)

```bat
install.bat                                  :: окружение, PyTorch с CUDA, тесты

python fetch_roboflow.py                     :: последняя версия датасета из Roboflow → data/raw
python build_dataset.py data\raw\<проект>_v<N>_yolov11.zip
python build_dataset.py data\raw\<проект>_v<N>_yolov11.zip --config config\scene.yaml
python train.py defects                      :: → models/defects.pt + отчёт models/defects/<дата>.eval.md
python train.py scene --model yolo26n.pt     :: → models/scene.pt
```

Проверка на записях печати:

```bat
python run_video.py ..\ff5\printer_timelapse.mp4
python run_video.py --all --every 10         :: все записанные печати AD5M, сводка в runs/video/<дата>/index.md
```

Можно просто перетащить видео, папку или zip с кадрами на `run_video.bat`.

Эмуляция принтеров (камера + API как у AD5M) и сервис против них:

```bat
python emulate_printer.py --all --printers 5 --speed 30    :: окно 1
python monitor.py runs\emulation\printers.yaml             :: окно 2
```

`python -m pytest` — все тесты, включая работу сервиса против эмулированного парка принтеров.

## Данные: что было не так и что исправлено

- Из 2219 картинок Roboflow только 324 сняты камерой AD5M, остальное — интернет.
  Метрики поэтому считаются отдельно на кадрах AD5M — они главные.
- ~1000 объектов размечены полигонами вперемешку с рамками; старый `train.py`
  читал из полигона первые 4 числа как рамку — половина разметки была мусором.
  Теперь полигон переводится в описанный прямоугольник.
- 41 картинка загружена в Roboflow дважды с разной разметкой, часть копий
  лежала одновременно в train и test. Копии сводятся в одну, противоречивые выбрасываются.
- Деление train/val/test было перекошено (трещин в train 46, в valid 554;
  паутины в train не было вовсе). Теперь деление по группам почти одинаковых
  картинок (отрезок одной печати не разрывается) со стратификацией по классу и источнику.
- Старые модели учились на CPU 1–3 эпохи (mAP50 ≈ 0.07). Теперь — GPU, до 150 эпох.

## Текущее состояние (26.09.2026)

**Приёмка того, что стоит в exe** (ONNX + правило тревоги приложения, `docs/acceptance.md`):
целые записанные печати AD5M, кадр раз в 10 с; в каждую печать вклеено ~3 искусственных
сбоя (растущий комок из вырезок, которых модель не видела). Порог выбран на записях из
обучения, проверен на отложенных печатях (`config/holdout.yaml`).

| | часов | ложных остановок | настоящие сбои | искусственные | до остановки |
|---|---:|---:|---|---|---:|
| записи из обучения | 72 | **0** | 1 из 3 | 39 из 43 | 129 с |
| отложенные печати | 24 | **0** | 1 из 2 | 17 из 18 | 69 с |

Две модели брака (YOLO26s + RF-DETR small, `build/models/models.yaml`): сбой засчитывается, только если
его видят обе на одном месте; правило 3 из 5, порог 0.25, подтверждение по месту. Запас: у пары
0 ложных остановок при любом пороге 0.2–0.7 на всех 96 ч (у одной YOLO первая — уже на 0.3).

Честно о границах: настоящих сбоев в записях всего 5, модель уверена в них слабо (0.55–0.7) —
пропущен комок выдавленного пластика и гнездо нити, оставшееся от прошлой печати. Цифры
по полноте — в основном по искусственным сбоям. Главное, что нужно дальше, — записи
настоящих сбоев (`docs/failure_session.md`) и дообучение на них.

История (модель до дообучения на своих кадрах):

Модели: `models/defects.pt` (YOLO26s, 150 эпох), `models/scene.pt` (YOLO26n, 86 эпох).
Полные отчёты — `models/<модель>/<дата>.eval.md`.

**Модель сцены** (test, 44 кадра AD5M): пластина PEI mAP50 0.995, голова 0.957,
тестовая линия 0.995 — работает. «Пластина лежит криво» — 0.04, не работает (мало примеров), заглушена.

**Модель брака** (test): на всех картинках mAP50 0.257 (старая модель — 0.07);
на кадрах AD5M mAP50 0.067. По кадрам AD5M при пороге 0.25: проблема замечена
на 51% кадров, ложная тревога на 13% чистых. Спагетти и струны на своей камере
модель почти не находит — она выучила их по интернетным фото. Это ожидаемо: своих
кадров с браком в обучении единицы. Попытка без новой разметки (кадры AD5M ×4,
выбор эпохи по кадрам AD5M, `models/defects_ad5m.pt`) лучше не стала.

**Прогон по 32 записанным печатям AD5M** (`runs/video/final/index.md`, 25 из них
модель не видела): остановка из-за брака в 4 печатях из 25 — две похожи на правду
(комок спагетти 04.03, кривые детали 15.06), две ложные (ровные ряды клипс 05.03,
огрызок тестовой линии 24.03). Кадры каждой тревоги — в `alerts/` папки печати.
Какие печати на самом деле были бракованными, неизвестно — точный процент пойманного
брака по записям не посчитать, нужна разметка.

**Эмуляция** (`runs/monitor_demo`): три эмулированных AD5M на записях 04.03 (спагетти),
18.04 (мусор на столе), 29.04 (чистая) — сервис поставил на паузу первый через 9 с
после старта, по второму только уведомил, третий не тронул.

Наблюдение для «нет покрытия PEI»: 14.05 печать шла на стекле — модель сцены
увидела «пластину PEI» с уверенностью 0.56 вместо обычных 0.9+. Для надёжной
проверки нужен отдельный класс (например `glass_plate`) и десяток размеченных кадров.

## Разметка своих кадров (tools/review.py)

Полуавтоматическая разметка партии из `extract_frames.py`:

1. `python tools\review.py candidates data\to_label\batch1` — модели дают кандидатов брака
   (с буквами) и стол/голову/тестовую линию/руки (берутся автоматически, уверенность ≥ 0.5).
2. `python tools\review.py sheets data\to_label\batch1` — листы 3×3 кадра в порядке
   времени внутри печати, с буквами кандидатов и сеткой координат.
3. По каждому листу — решения в `review\decisions\*.txt` (правила и формат —
   `review\GUIDE.md`): оставить кандидатов, «брака нет», добавить объект точкой
   (рамку строит SAM) или рамкой, флаги стекло / нет пластины / камера мимо / пластина криво.
   `python tools\review.py zoom … NNNN 3` — кадр в полном размере; `check` — проверка файла.
4. `python tools\review.py apply data\to_label\batch1` → `data\labeled\batch1` (формат YOLO),
   дальше `update_data.py` добавит её в оба датасета.

## Как улучшать модель

Главный рычаг — разметка кадров своей камеры. На диске 54 тыс. кадров
с 32 печатей AD5M; отбор оставляет ~3 тыс. непохожих:

1. `python extract_frames.py --out data\to_label\batch1 --prelabel` — кадры
   с предразметкой текущими моделями, zip рядом. **Первая партия уже готова:**
   `data\to_label\batch1.zip`, 2978 кадров с 32 печатей. В предразметке стол и голова
   почти всегда верны; мусор и коробление — с лишними рамками; «пластина криво» — в
   основном ложные, их удалять.
2. Загрузить zip в новый проект Roboflow (Upload → YOLO), поправить рамки.
   Классы — сразу обеих моделей (`classes.txt`).
3. `python fetch_roboflow.py --project <новый проект>` и собрать датасеты из
   обоих архивов: `python build_dataset.py data\raw\*.zip` (и с `--config config\scene.yaml`).
4. `python train.py defects`, `python run_video.py --all --every 10`.

Что особенно нужно снять и разметить (сейчас примеров нет или очень мало):
отрыв модели от стола (`detached`), печать без пластины, пластина лежит криво
(`pei_misplaced`), слетевшая крышка обдува (`head_no_cover`), руки в кадре.

## Сервис и API принтера

Драйверы — `guard/adapters/flashforge.py` (HTTP 8898 + TCP 8899) и `guard/adapters/moonraker.py`;
контрактные тесты гоняют каждый драйвер против эмулятора (`tests/product/test_drivers_contract.py`).
Форматы взяты из разборов протокола сообществом и старых наработок, проверены только на
эмуляторе — **перед запуском парка сверить на одном живом AD5M** («Проверить подключение»,
пауза/продолжить, `logs/guard.log`). Старый `ddet/printer.py` + `monitor.py` — прототип, заменён `guard`.

Модели на кадрах разных принтеров запускаются одним пакетом (`Detector.batch`),
так один GPU обслуживает сотни камер при опросе раз в несколько секунд.

## Что заменено из старых наработок

Старые папки (`..\detection`, `..\ff5imagesgraber`, `..\ff5`) не тронуты.

- `detection/app.py` — облачный инференс Roboflow; ключ API был прописан в коде (перенесён в `.env`).
- `detection/app_2.py` — разбор выхода ONNX под формат YOLOv5, для YOLO11 не работал.
- `detection/app_onnx.py` — номера классов сдвинуты на 1 (трещины не ловились вовсе,
  остальное подписывалось чужими именами).
- `ff5/printer_monitor.py` — сравнение соседних кадров без модели; токен Telegram-бота прописан в коде.
- `ff5imagesgraber/model/train.py` — ошибка с полигонами, пути на диск `P:\`, 1 эпоха на CPU.

Всё это заменяют `run_video.py`, `monitor.py` и `train.py` этого проекта.
